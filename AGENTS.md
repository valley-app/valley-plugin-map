# Map plugin

- Settings → Map → Map pins (17 Nov) runs top to bottom: the edge-to-edge 37px + 1px `settings-listpage-header` with the master switch, one description line, a `.map-sources-toolbar` with the source search (flex 1) and the compact accent Add source button (plain plus, icon and text in one inline-flex child, in a padded local wrapper; shown whenever the store exists, alone when there are no sources), the source list, then the Pin icons row in its own Section below the list. Never an oversized dashed Add placeholder.
- Pin sources are one flat list split by hairlines (17 Nov): no cards, shadows or hover borders. Every collapsed row is 44px on fixed columns: grip | chevron | static 24px disc (`--swatch-fill/-ring/-on`) | name + one-line sub-line | count | switch. The sub-line reads `key = value` (or "Choose a property and value"), then the folder (or "Whole realm"), then, as the only red on the page, `none has a usable “field”` when the rule matches notes but none can be located. Zero matches are a neutral "0 notes found". A source that is turned off reads "Turned off · rule", is dimmed through text colour tokens, shows "–" as its count and has its row switch off and disabled. When asked to remove red source errors, remove the identified broken rules from the development configuration rather than hiding validation warnings.
- Search fields use the shared container focus ring only; explicitly clear native input focus and focus-visible borders, outlines, and shadows, and verify the focused field in the sandbox. Put spacing around host buttons on a local wrapper so their measured bounds are not clipped.
- Keep the pin icon picker compact: small icon-only cells with accessible names and tooltips, not oversized captioned tiles.

- Collapsed pin sources mount no host-backed fields, colour pickers, icon-picker button or action widgets; their only host widget is the visibility `Toggle` (17 Nov). An expanded source turns its name cell into the full-width title field with the status line under it ("24 notes found · 21 on the map · 3 not located yet"), then, inset to the name column, sentence-case `settings-label` groups of local `settings-path-row` rows: Notes (Folder; Property and value as two fields joined by "="), Location (Location from as Segmented Address | Coordinates; Location property), Pin (Icon and colours: round icon-only picker, fill and ring `ColorField`s, left-aligned in the control column; Pin title as Segmented Filename | Property plus Title property), Popup (Popup fields as a reorderable, removable `ChipsField`), then "Use this source" (a `Toggle` bound to `!hidden`, never a Hide/Show text button) and "Delete source" (two-click `ConfirmRemove`). A source added with Add source opens expanded. Counting lives in `ruleSummary`, `sourceStats` and `notLocatedYet` in `src/pinSources.ts`. Reordering is persisted shared drag ordering in Settings and the left sidebar; reordering filtered results preserves sources outside the filter.
- The left-sidebar Map pins tab is drawn like Favorites (15 Nov): a 38px bar (title, master eye, expand/collapse all, + that opens Map pins settings), then one row per source with chevron, white glyph on a disc in the source colour, name, count, eye and ⋯ menu; a source opens to list the notes it pins. Rows drag themselves (no visible grip) and Alt+↑/↓ reorders; reordering swaps only the listed sources. No switches in the sidebar; Settings keeps its switches.

- The Favourite Routes tab is the Favourite Places tree for routes (15 Nov): `src/RoutesTab.tsx` reuses PlacesTab's `useSetting`, `FolderEditor`, `pickIcon` and the generic helpers in `src/placeFolders.ts` (never a copy). A 38px ROUTES bar (collapse/expand all, master eye, add folder, + that clears the planner and reveals the right sidebar); route rows show glyph, name, distance, eye and ⋯ only. Folders live in the hidden `routeFolders` setting, membership/order/icon in `routeFiling` (array order = tree order), eyes in `hiddenRouteFolders`, `hiddenRoutes`, `routesHidden`, folding in `collapsedRouteFolders`. Change icon in every ⋯ menu (places, routes, folders) is a submenu listing the map icons with the current one checked (`iconSubmenu`); Color opens the palette popover (`pickColor`, with No color) about 80 ms after the menu closes, because a popover opened while the menu hands focus back dismisses itself as a window blur. Never a modal (15 Nov). Menu icons must render to static SVG without hooks (`MenuPinGlyph`, SVG `ColorDot`); a hooked glyph like `PinGlyph` becomes a slow nested surface per entry and shows no icon. Visible saved routes are drawn by `MapEngine.setSavedRoutes` below the open plan in their folder's colour (grey default); keep the active plan untouched.


- `map.sidebarTab` snapshots may carry planner keys (`segments`, `route`, `journeys`, `journey`, `tiles`); Map then draws `JourneyPanel` in Valley's style instead of the plain field/button form, which stays for older providers. Keep both repository copies of `sidebarContract.ts` byte-identical and every new key optional. `look: 'sbb'` switches `JourneyPanel` to the SBB app's colours (CSS `light-dark()` under `.is-sbb`, following the host's `color-scheme`); `earlier`/`later`, `route.when`, `tileSwipe`, journey `day`/`stops`/`occupancy`, badge `category`/`number` and tile `place`/`size` stay optional and generic, so another provider can use them in Valley's own style.
- `JourneyPanel` layout (17 Nov): the segment bar and an opened connection's back bar (`panel-tool-btn` chevron, "Back to connections", then the trip title on one line; Escape inside the panel goes back) are sticky 38px bars with an opaque background; the summary card does not repeat the title. Station suggestion rows are 37px with one-line titles. `route.when` is drawn inline by `WhenFields` with the SDK `DateField`/`TimeField`, a two-option Departure/Arrival toggle and a round `panel-tool-btn` Now button, applying each change at once; never a plugin-drawn wheel sheet or Apply. `MapSidebarWhen.label`, `days` and the sheet texts are optional leftovers for older providers.
- Placed tiles (17 Nov): a `map.sidebarTab` tile may carry `column`, `row`, `columns`, `rows`; `JourneyPanel` then sets its `grid-column`/`grid-row` on a four-column `.map-tiles.is-placed` grid, so empty cells stay empty (no dense refill). Tiles without them keep the `size` auto-flow. Providers place fixed tiles (SBB's current location, from, to) as the grid's last row directly under the tiles with the same gap, never pinned to the sidebar bottom (17 Nov); swipes and the swipe line work across gaps.
- Journey-form stops reorder by drag only when the provider sets `route.reorder` (17 Nov): the form looks unchanged at rest (no grip, same rows, spine, rings and swap). The spine starts a drag at once, the rest of a row after a few pixels and never inside a focused field; while dragging the source row dims, a rounded chip (ring and text on `--container-color-alt`, soft shadow) follows the pointer, and the shared insertion line with its dot (`--drop-knob`/`--drop-indicator-fill`) marks the gap. Alt+↑/↓ in a field moves that stop; the empty trailing via row never moves.
- While station suggestions (`rows`) show for a stop being typed in, `JourneyPanel` lists nothing else (no caption, earlier/later, day headers, cards, opened connection or message) for any provider; Escape or leaving the field hides them and the kept results return (17 Nov). The date/time row starts at the stop rows' 10px inset and its date and time fields are only as wide as a ten-character date / `HH:mm` plus the icon (no stretching).
- Departure boards (journeys without `arrival`, 17 Nov) are one grid with a subgrid per row box: time | pictogram and badge | destination (shrinks first, down to nothing, ellipsis) | delay | platform, the badge column as wide as the widest listed badge. A late entry shows only its expected time, in red; `delay` stays in its own right-hand column; `platformChanged` colours the platform. Departure-board rows are always one line (17 Nov): time and badge stay complete, a line badge always shows its complete text at its natural size everywhere (a column is as wide as its widest badge; a badge is never stretched, shrunk or truncated), the destination starts 8px after the line column, and only the destination (then the platform) truncates with an ellipsis; never a second line. Without `when.text.departure`/`arrival` the date/time row has no departure/arrival choice.
- A provider may supply the glyph of its result rows (`rowIcon`: viewBox, path, optional fillRule); Map draws it in the look's icon colour (`--sbb-text` under `look: 'sbb'`, never accent blue) and its own pin otherwise. Provider artwork stays in the provider's repository, never in Map (17 Nov).
- `route.when` also carries an optional `picker` (`'grid' | 'wheel'`, 17 Nov): `WhenFields` passes it to the SDK `DateField`/`TimeField` when set and omits it otherwise; the SBB date and time fields use Valley's shared SDK fields with the wheel design, asked for by the provider through the optional `when.picker` key.
- Sidebar-tab overlays (17 Nov): a `map.sidebarTab` snapshot may carry `overlay` (`paths` of `[lng, lat]` points with optional `stops`, `markers` of kind origin/destination/station/change, `color`, `fit`). `ExtensionPanel` hands it to `MapStore.setSidebarOverlay`, which validates and bounds it (8 paths, 2000 points, 500 stops, 64 markers, `#rgb`/`#rrggbb` colours), and `MapEngine.setSidebarOverlay` clones it into the map surface's realm and draws straight lines with a white casing, stop dots and circle markers between the saved routes and the open plan (`sig-sidebar`). Stops and markers carry names (`stopNames`, `label`) shown as a small tooltip on hover and kept after a click (`map-stop-popup`, DOM popup, so no style glyphs are needed); an overlay `attribution` recreates the source with it so the map credits the path's data on styles that do not (satellite, offline). Only the main Map page shows it: it never opens the Map page, is never saved and never changes places, saved routes, pins or the plan. It clears when the tab is left, its provider goes away or the snapshot drops it; the camera fits it only when `fit` changes or it reappears, never while the user pans. Map draws only what a provider supplies; a timetable provider sends stop-to-stop lines from supplied stop coordinates, never vehicles; track geometry comes from the provider, never from Map.
- A planner holding only the origin it filled in from the live position draws no lettered marker (`shownWaypoints`, 17 Nov): that is not a plan and only repeated the position as an "A" beside a sidebar overlay; the planner form still shows it and the live-location dot stays.
