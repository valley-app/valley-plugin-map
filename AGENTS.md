# Map plugin

- Settings → Map sub-pages run Map pins, Embed, Codeblock, Mapbox, OpenRouteService, Plugins (18 Nov). The main page's Notes section carries the Map pins switch (`pinsEnabled`, on by default, gear to its page while on); Map pins is `visibleWhenSetting: "pinsEnabled"` like Mapbox and OpenRouteService. Off hides the sub-page and the sidebar's Map pins tab (an open pins tab falls back to Search), draws no note pin or coordinate dot and geocodes nothing; saved sources stay untouched.
- The SBB-look product pictograms in `JourneyPanel` are Phosphor Icons fill glyphs (MIT, 256 grid), never SBB's own pictograms (18 Nov).
- Settings → Map → Map pins (17 Nov) runs top to bottom: the edge-to-edge 37px + 1px `settings-listpage-header` with the master switch, one description line, a `.map-sources-toolbar` with the source search (flex 1), one icon-only expand all / collapse all button (`panel-tool-btn`; chevrons-down-up while a source is open, chevrons-up-down when all are closed) and the compact accent Add source button (plain plus, icon and text in one inline-flex child; shown whenever the store exists), then the source list. No Pin icons row on the page: the icon popover carries Open icon folder and Refresh. Add source saves the new source first in the list, opens it and scrolls the list to the top. Never an oversized dashed Add placeholder. The header bar stays on top while the list scrolls (17 Nov): the `pins` settings section declares `"layout": "fill"` in `config.json` (host `settings-fill` 3bb9a668 or later; an older host rejects the key), and `PinsSection` is a `.map-pins-frame` (`data-plugin-widget-layout="fill"`, pane inset cancelled with `margin: 0 -10px`) holding an SDK `ScrollPanel fill` with the bar in its `header` slot and description, toolbar and list as its body; each nested document supplies its own 10px inset and the list ends with 16px bottom padding. Never put the bar back into the scrolling body, and never rely on `position: sticky` in a content-height settings frame.
- Pin sources are one flat list (17 Nov): a straight 1px hairline between every source, edge to edge of the pane like the header line, also under the toolbar and under the last source; no cards, boxes, shadows or hover borders. Every head is 44px on fixed columns: grip | static 24px disc (`--swatch-fill/-ring/-on`) | name + one-line sub-line | count | chevron | switch. The chevron sits directly left of the switch; a click anywhere on the head except grip and switch opens or closes the source, and a mouse click leaves no focus box (ring for keyboard focus only). Opening or closing never changes the head: same height, name, sub-line, count and switch at the same place; never turn the name into a field in the head. The sub-line reads `key = value` (or "Choose a property and value"), then the folder (or "Whole realm"), then, as the only red on the page, `none has a usable “field”` when the rule matches notes but none can be located. Zero matches are a neutral "0 notes found". A source that is turned off reads "Turned off · rule", is dimmed through text colour tokens, shows "–" as its count and has its row switch off and disabled. When asked to remove red source errors, remove the identified broken rules from the development configuration rather than hiding validation warnings.
- Settings → Map (main page, 17 Nov): Map display has Map provider, Default basemap and Default zoom only. There is no Default centre and no Offline basemap: the map always opens at `DEFAULT_CENTER` (8.5417, 47.3769) and a saved `defaultCenter` or `offlineBasemapPath` is not read (`resolveSettings`); do not bring either row or schema field back. The offline basemap is removed as a feature (17 Nov): no PMTiles protocol, style, backend `offlineRange` handler or `pmtiles` dependency. Default zoom is the SDK `RangeField` like Appearance → Font size (step marks, number box, reset) in steps of five, 0 to 25 (`ZOOM_STEP`, `ZOOM_MAX`, default 10); a saved value between two steps shows on the nearest one, and the map itself stops at its closest zoom. The Mapbox and OpenRouteService rows under Services open their account page with the Remix `user-settings-line` glyph (`UserSettings` in `src/icons.tsx`), not a pencil.
- Settings → Map → Plugins (17 Nov, `plugins` section, host icon `blocks`, right after Map pins) is the same page as Calendar's Plugins: the bordered intro line, then one SDK `PluginCard` per plugin that contributes a `map.sidebarTab`, with its name, version, author and description from the installed plugin list (backend `sidebarPlugins`, `api.plugins.list()`), a gear that opens that plugin's own settings (`plugin:<id>`, only when it has a settings page) and a switch. The switch hides that plugin's tabs in the Map sidebar only: plugin ids switched off are saved in the hidden `hiddenSidebarPlugins` setting and `useSidebarExtensions` leaves them out; the plugin itself stays enabled. A new contract a plugin can contribute to Map gets its providers listed on this page, never a page of its own.
- Closing the search closes its route (17 Nov): `clearSearch` (the search field's ×, Escape, the place card's ×) also clears the planner when Directions was opened from that card, so no route stays on the map behind an empty Search tab. A route planned elsewhere (a saved route, a command, the right sidebar) is left alone.
- Eyes hide everything (17 Nov): a note that a pin source matches is that source's pin whether its eye is open or closed and never falls back to the generic purple dot (`sig-pins-dot`). The generic dots (notes with coordinates that no source matches) follow the Map pins master eye: with at least one source in use and no eye open, none is drawn. A source that is turned off (`hidden`) has no eye and never counts as an open one, whatever its saved `visible` says (`refreshDerived` in `src/store.ts`).
- Route lines never travel in bulk (17 Nov): one host message carries at most 100 000 values and a route line is thousands of `[lng, lat]` pairs. `routeStore.read` reads the route list without `geometry` and the lines apart, four routes at a time, halving a chunk the host refuses (`routeGeometries`); a route too big on its own is listed without its line. `list-routes` answers without `geometry` (`export-route` gives one route's line). Reading every line with the rows made the whole start-up read fail at 25 saved routes: the map opened empty, at the default centre, with every generic dot showing. Never add a read, command result or snapshot that carries all routes' lines in one value.
- `save-place` takes optional `folder` (a folder id from the `placeFolders` setting), `icon` (a map icon id) and `color` (17 Nov), so a place can be filed by command; folders, route folders and per-route folder, icon and colour are the `placeFolders`, `routeFolders` and `routeFiling` settings.
- Search fields use the shared container focus ring only; explicitly clear native input focus and focus-visible borders, outlines, and shadows, and verify the focused field in the sandbox. Put spacing around host buttons on a local wrapper so their measured bounds are not clipped.
- Keep the pin icon picker compact: small icon-only cells with accessible names and tooltips, not oversized captioned tiles.

- Collapsed pin sources mount no host-backed fields, colour pickers, icon-picker button or action widgets; their only host widget is the visibility `Toggle` (17 Nov). An open source shows, under its unchanged head and inset to the name column, a compact form (`.map-source-form`): a 132px label column directly followed by the controls (up to 440px), 32px rows, hairlines only between groups, never the wide label-left / control-far-right settings rows. Order: Name; Notes (Folder; Property as `[key] = [value]` with the status line "24 notes found · 21 on the map · 3 not located yet" directly under it); Location (Read from: Segmented Address | Coordinates with the property field under it and a one-line hint); Pin (Look: round icon-only picker, fill and ring `ColorField`s; Title: Segmented Filename | Property plus its property field; Popup: reorderable, removable `ChipsField`); then one footer row with "Use this source" (a `Toggle` bound to `!hidden`, never a Hide/Show text button) at the left and the two-click Delete source at the right. Below 480px labels stack above their controls. The host copies ancestor class names into each host widget's own DOM, so never put pseudo-elements or layout rules on `.map-source-list` and its ancestors that would also apply inside a widget. Counting lives in `ruleSummary`, `sourceStats` and `notLocatedYet` in `src/pinSources.ts`. Reordering is persisted shared drag ordering in Settings and the left sidebar; reordering filtered results preserves sources outside the filter.
- The left-sidebar Map pins tab is drawn like Favorites (15 Nov): a 38px bar (title, master eye, expand/collapse all, + that opens Map pins settings), then one row per source with chevron, white glyph on a disc in the source colour, name, count, eye and ⋯ menu; a source opens to list the notes it pins. Rows drag themselves (no visible grip) and Alt+↑/↓ reorders; reordering swaps only the listed sources. No switches in the sidebar; Settings keeps its switches.

- The Favourite Routes tab is the Favourite Places tree for routes (15 Nov): `src/RoutesTab.tsx` reuses PlacesTab's `useSetting`, `FolderEditor`, `pickIcon` and the generic helpers in `src/placeFolders.ts` (never a copy). A 38px ROUTES bar (collapse/expand all, master eye, add folder, + that clears the planner and reveals the right sidebar); route rows show glyph, name, distance, eye and ⋯ only. Folders live in the hidden `routeFolders` setting, membership/order/icon in `routeFiling` (array order = tree order), eyes in `hiddenRouteFolders`, `hiddenRoutes`, `routesHidden`, folding in `collapsedRouteFolders`. Change icon in every ⋯ menu (places, routes, folders) is a submenu listing the map icons with the current one checked (`iconSubmenu`); Color opens the palette popover (`pickColor`, with No color) about 80 ms after the menu closes, because a popover opened while the menu hands focus back dismisses itself as a window blur. Never a modal (15 Nov). Menu icons must render to static SVG without hooks (`MenuPinGlyph`, SVG `ColorDot`); a hooked glyph like `PinGlyph` becomes a slow nested surface per entry and shows no icon. Visible saved routes are drawn by `MapEngine.setSavedRoutes` below the open plan in their folder's colour (grey default); keep the active plan untouched.


- `map.sidebarTab` snapshots may carry planner keys (`segments`, `route`, `journeys`, `journey`, `tiles`); Map then draws `JourneyPanel` in Valley's style instead of the plain field/button form, which stays for older providers. Keep both repository copies of `sidebarContract.ts` byte-identical and every new key optional. `look: 'sbb'` switches `JourneyPanel` to the SBB app's colours (CSS `light-dark()` under `.is-sbb`, following the host's `color-scheme`); `earlier`/`later`, `route.when`, `tileSwipe`, journey `day`/`stops`/`occupancy`, badge `category`/`number` and tile `place`/`size` stay optional and generic, so another provider can use them in Valley's own style.
- `JourneyPanel` layout (17 Nov): the segment bar and an opened connection's back bar (`panel-tool-btn` chevron, "Back to connections", then the trip title on one line; Escape inside the panel goes back) are sticky 38px bars with an opaque background; the summary card does not repeat the title. Station suggestion rows are 37px with one-line titles. `route.when` is drawn inline by `WhenFields` with the SDK `DateField`/`TimeField`, a two-option Departure/Arrival toggle and a round `panel-tool-btn` Now button, applying each change at once; never a plugin-drawn wheel sheet or Apply. `MapSidebarWhen.label`, `days` and the sheet texts are optional leftovers for older providers.
- Placed tiles (17 Nov): a `map.sidebarTab` tile may carry `column`, `row`, `columns`, `rows`; `JourneyPanel` then sets its `grid-column`/`grid-row` on a four-column `.map-tiles.is-placed` grid, so empty cells stay empty (no dense refill). Tiles without them keep the `size` auto-flow. Providers place fixed tiles (SBB's current location, from, to) as the grid's last row directly under the tiles with the same gap, never pinned to the sidebar bottom (17 Nov); swipes and the swipe line work across gaps.
- Journey-form stops reorder by drag only when the provider sets `route.reorder` (17 Nov): the form looks unchanged at rest (no grip, same rows, spine, rings and swap). The spine starts a drag at once, the rest of a row after a few pixels and never inside a focused field; while dragging the source row dims, a rounded chip (ring and text on `--container-color-alt`, soft shadow) follows the pointer, and the shared insertion line with its dot (`--drop-knob`/`--drop-indicator-fill`) marks the gap. Alt+↑/↓ in a field moves that stop; the empty trailing via row never moves.
- While station suggestions (`rows`) show for a stop being typed in, `JourneyPanel` lists nothing else (no caption, earlier/later, day headers, cards, opened connection or message) for any provider; Escape or leaving the field hides them and the kept results return (17 Nov). The date/time row starts at the stop rows' 10px inset and its date and time fields are only as wide as a ten-character date / `HH:mm` plus the icon (no stretching).
- Departure boards (journeys without `arrival`, 17 Nov) are one grid with a subgrid per row box: time | pictogram and badge | destination (shrinks first, down to nothing, ellipsis) | delay | platform, the badge column as wide as the widest listed badge. A late entry shows only its expected time, in red; `delay` stays in its own right-hand column; `platformChanged` colours the platform. Departure-board rows are always one line (17 Nov): time and badge stay complete, a line badge always shows its complete text at its natural size everywhere (a column is as wide as its widest badge; a badge is never stretched, shrunk or truncated), the destination starts 8px after the line column, and only the destination (then the platform) truncates with an ellipsis; never a second line. Without `when.text.departure`/`arrival` the date/time row has no departure/arrival choice.
- A provider may supply the glyph of its result rows (`rowIcon`: viewBox, path, optional fillRule); Map draws it in the look's icon colour (`--sbb-text` under `look: 'sbb'`, never accent blue) and its own pin otherwise. Provider artwork stays in the provider's repository, never in Map (17 Nov).
- `route.when` also carries an optional `picker` (`'grid' | 'wheel'`, 17 Nov): `WhenFields` passes it to the SDK `DateField`/`TimeField` when set and omits it otherwise; the SBB date and time fields use Valley's shared SDK fields with the wheel design, asked for by the provider through the optional `when.picker` key.
- Sidebar-tab overlays (17 Nov): a `map.sidebarTab` snapshot may carry `overlay` (`paths` of `[lng, lat]` points with optional `stops`, `markers` of kind origin/destination/station/change, `color`, `fit`). `ExtensionPanel` hands it to `MapStore.setSidebarOverlay`, which validates and bounds it (8 paths, 2000 points, 500 stops, 64 markers, `#rgb`/`#rrggbb` colours), and `MapEngine.setSidebarOverlay` clones it into the map surface's realm and draws the lines of paths with at least two points (white casing), stop dots and circle markers between the saved routes and the open plan (`sig-sidebar`). Stops and markers carry names (`stopNames`, `label`) shown as a small tooltip on hover and kept after a click (`map-stop-popup`, DOM popup, so no style glyphs are needed); an overlay `attribution` recreates the source with it so the map credits the path's data on styles that do not (satellite). Only the main Map page shows it: it never opens the Map page, is never saved and never changes places, saved routes, pins or the plan. It clears when the tab is left, its provider goes away or the snapshot drops it; the camera fits it only when `fit` changes or it reappears, never while the user pans. Map draws only what a provider supplies; a path of fewer than two points draws only its stops, unconnected (17 Nov), and the camera fits stops too; a timetable provider sends its stops as points and lines only along track geometry it supplies, never straight stop-to-stop lines and never vehicles; track geometry comes from the provider, never from Map.
- A planner holding only the origin it filled in from the live position draws no lettered marker (`shownWaypoints`, 17 Nov): that is not a plan and only repeated the position as an "A" beside a sidebar overlay; the planner form still shows it and the live-location dot stays.
- Ride info (17 Nov): a ride leg may carry `action` and `occupancy`, and the snapshot a `ride` (`title`, `back`, `badge`, optional `number`, `direction`, `occupancy`, `stops` of `{ name, arrival?, departure?, platform?, role?: 'board' | 'alight' | 'pass' | 'after', occupancy? }`). While `ride` is set `JourneyPanel` draws `RideInfo` instead of the opened connection: the sticky 38px back bar (title = `ride.title`, button "Back to the connection", Escape runs `ride.back`), a header card, then one row per stop on one spine (arrival above departure, departure bold, a lone time bold; name truncating with an ellipsis; platform at the right; a late time keeps its planned clock and shows the provider's `MapSidebarTime.delay` text, else the expected time, on a line under it in the late colour, with name, platform and dot staying on the main time's line), a late boarding, alighting or passed stop's dot in the late colour; no legend in the ride info or the opened connection; opened-connection leg times show the same delay line under the time, board/alight as filled dots in bold, ridden-past stops as small rings, stops outside the traveller's part (`after` or no role) dimmed with their spine segments. Map draws only the stops and values the provider sends: ride info lists only provider-supplied stops and values, and the stops after alighting only from what the provider matched exactly; never attributes, train formation or fares unless a contract key carries them. The overlay is the provider's: a provider may send a path only for an opened connection and none for its list.
- Sidebar tabs live in `src/tabs/<tab>/` (17 Nov): `search` (the shared place search, `PlaceCard`, and the A-to-B planner under `directions/`), `favorite-place`, `favorite-route` and `note-pin`. Each folder exports one `MapTab` from its `index.ts` (`id`, `labelKey`, `Icon`, `Panel`, optional `focusOnClick`; `src/tabs/types.ts`) and `src/tabs/index.ts` lists them in default order; `Panel.tsx` knows a built-in tab only by that description, as it knows a plugin's tab only by `map.sidebarTab`. A tab's own code stays in its folder; what the two favourites trees share is `src/tabs/shared/tree.tsx`. Tab ids (`search`, `places`, `routes`, `pins`) are saved in the tab order and the session and never change. Provider tabs (SBB) stay plugins.
- Selected controls use the tab strip's look (17 Nov): `--accent-tint-bg` with `--title-color`, never an accent border or accent text. That covers the place card's switched-on Directions and Saved buttons, the travel-mode segment, and the round map controls (`.map-round-btn.active`, tint laid over the opaque surface so tiles never show through).
- Map's own A-to-B planner is drawn by `JourneyPanel` in Valley's style (17 Nov): `src/tabs/search/directions/directionsTab.ts` is an internal `map.sidebarTab`-shaped provider over the store's stops, so the form is the one a timetable plugin gets: start, vias, destination on one spine, swap, drag to reorder, and always one empty via row (a filled via gets a new empty row under it, an emptied via row goes). Typing in a stop lists place suggestions under the form (saved places first); an empty focused field offers the current location and the favourites; Enter takes the first hit; text that was not picked goes when the field is left. `RouteCard` adds the travel modes above and the result below; both sidebars use it. `JourneyPanel`'s `onStopEnter`/`onStopBlur` are component props for this planner only, never contract keys.
- A plan that fails always says why (17 Nov): `routing.ts` throws a `RouteProblem` with a reason (`no-route`, `off-road`, `too-far`, `same-place`, `offline`, `busy`, `service`), the store keeps it as `planProblem` (and clears the old line from the map), and the form shows `routeProblemText` in plain words with a Try again button. With one end missing the form says which. Never show a raw "Routing failed (400)".
- Favourites trees, places and routes alike (17 Nov): a folder without an icon of its own shows the open folder while expanded and the closed one while folded; a row inside a folder has no glyph (`.is-filed`, its name under the folder's name) and no Change icon or Color in its menu or editor; only an item outside every folder has an icon and colour of its own (a route's colour is `routeFiling[].color`). On the map an item in a folder is drawn with that folder's own icon and colour (`itemLook` in `src/placeFolders.ts`), never the item's and never those of the folder above; a saved icon or colour is kept for when the item leaves the folder.
- The map's click card and the sidebar's place card (17 Nov): coordinates and address copy on a click (`CopyText`: the copy glyph turns into a check). The click card has Directions beside Save place: `store.directionsTo` makes the point the picked result and the destination of a fresh route from the current location, and the left sidebar opens on the Search tab.
